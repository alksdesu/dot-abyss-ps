# 其他常驻战斗模式

支持深渊、独立厄灾、训练中心、普通遭遇战、势力战和常驻外传。主线见[主线战斗与教程](main-story-battle.md)，活动玩法见[活动与本地复刻](events-and-reruns.md)。适配版本与主表内容数量见[更新记录](../changelog.md#内容快照)。

## 模式范围

| 模式 | 流程 |
| --- | --- |
| 深渊 | 入场、冻结队伍、移动、战斗、代码、事件、商店、保管、跳层、球盘、归还与结算 |
| 厄灾 | 四槽刷新、巡逻、召唤、设施布阵、燃料消耗、战斗、当日扫荡、普通与特殊 Boss 推进 |
| 训练中心 | 解锁、已读、进入、胜利或退出、首次奖励、符合条件时免打领取、最高伤害 |
| 普通遭遇战 | 使用普通遭遇组，随派遣时间出现、到期、补给与补给购买、开战、结算、已通关类型扫荡 |
| 势力战 | 按星期开放、每日次数、逐关推进、首次奖励、已通关层周回 |
| 常驻外传 | 按顺序阅读与挑战、回看、首领奖励、重复挑战与扫荡、通关次数任务 |

## 共用战斗与模式隔离

`gameplay_battle_modes.py` 绑定每种模式的主表、原生 `quest_type`、敌人和掉落来源。各模式沿用同一套会话编号、实体 ID、战报来源校验与请求回执。

普通战斗使用玩家编队；固定训练可以使用原生的 `party_no=0`。深渊保存独立队伍快照和 HP 状态，临时物品与局外背包分开结算。不同模式的完成或退出请求不能结束另一种模式的战斗。

深渊角色技能通过 `m_abilities` 解析实际效果 ID，并依据突破取得的觉醒层选择。抗性等级、装备主表与强化次数由原生角色构造器继续计算，不能重复叠进基础属性。代码的战斗效果与分类战斗技能通过原生代码记录应用；侵蚀、结算和球盘解锁等服务端效果分别在对应流程消费。

研究树检查前一棋盘的中心节点，以及本棋盘中心节点所需的其他研究。检查点入场同时检查历史通关层数和研究解锁层数；额外掉落、分类侵蚀加成与保管容量会影响实际流程。终层仍允许完成待选代码，未归还结算的远征不能被新入场覆盖。

深渊每段按本次投入门票冻结积分倍率，下一段重新计算；免费与一票为基础倍率。额外门票只增加该段积分，不重复放大研究点或固定掉落。秘密藏宝格遵循主表使用次数上限，在路径和侵蚀条件满足时揭示，重启保留揭示状态。

训练中的防卫场景仍使用探索型请求 DTO；报文字段校验与画面类型分别绑定。试打退出只提交时间与伤害，不作为胜利或发奖处理。

势力战的同势力 3／5／10 人编队补给属于客户端自动应用的战斗增益，技能档位由完整主表下发。服务端不再把它当作额外物品奖励发放。

训练完成、试打伤害、势力挑战次数与首次推进分别更新对应任务。势力指定关卡的礼包条件按关卡 ID 判断。既有厄灾最高等级参与终身任务判断，不要求为恢复历史进度再打一场。

常驻外传有独立进度，使用原生 `quest_type=8`；剧情节点按小说组查找脚本。前 11 节完成即显示整篇完成，第 12 节是单独的终章周回关，首次完成后才能扫荡，每次消耗 40 体力。首领奖励每节只发一次，剧情回看不重复计数，战斗与扫荡会累计任务要求的通关次数。当前外传没有额外开放限制；后续主表若增加尚未核实的限制类型，会明确报错，不能静默忽略。

遭遇战掉落表的行 ID 不全局唯一，按 `(m_encounter_quest_id, id)` 保存。原始 ID 不被改写，全部原始记录均保留。

## 宝箱遭遇

宝箱层使用原生模型的三档默认配置：S 为 120 秒与 `BoxGold`，A 为 180 秒与 `BoxSilver`，B 无时间上限与 `BoxBronze`。每档奖励有独立的本局 ID，战报只能领取已通过宝箱层中所报档位的奖励，不能同时领取三档。扫荡采用最高档。

奖励数量来自公开掉落池的本地抽选规则：默认 B/A/S 分别为 1/2/3 项，允许设为 0。不会从季节活动宝箱表借用配置。服务器不把整场战斗总耗时误当成宝箱层的局部计时。

## 时间、消耗与奖励

每日补给和厄灾刷新按日本时间 05:00 处理。势力战的星期开放按原生服务器自然日判断，`weekday % 7` 中 0 表示周日；开放星期与次数刷新是两个条件。

厄灾扫荡要求当天存在胜利记录，并受已解锁的可扫荡等级约束。已开战会话保留原槽位和版本，跨日后不会把旧战报结算到新 Boss。普通遭遇开战时必须未过期，合法开战后到期仍可完成；退出后过期遭遇会移除。

所有消耗、奖励、记录变化和回执共用存档事务。批量操作中后续步骤失败时回滚整批；背包溢出交给已有邮件逻辑。研究引起的设施等级变化会在同次响应中同步，等级取主表定义的结果而非重复叠加。

Boss 解锁、厄灾升级和训练关卡开放使用已核对的原生通知结构。请求重放刷新所涉及的当前记录，不把玩家界面退回旧状态。

## 本地规则

缺少原服服务器算法的部分明确使用本地策略，配置位于数据目录的 `gameplay-rules.json`。原始主表不会被覆盖。

| 配置 | 默认值 | 含义 |
| --- | ---: | --- |
| `nether_free_entries_per_day` | 1 | 深渊每日免费入场 |
| `nether_initial_code_limit` | 8 | 初始代码容量 |
| `nether_initial_code_reloads` | 1 | 初始代码重抽次数 |
| `nether_starting_gold` | 100 | 初始局内金币 |
| `nether_score_per_floor` | 100 | 本地楼层结算分数 |
| `nether_score_multiplier_per_extra_ticket` | 1 | 每张额外门票增加的本段积分倍率，设为 0 关闭 |
| `nether_points_per_code` | 1 | 本地代码结算点数 |
| `nether_random_drop_probability_per_mille` | 300 | 深渊本地素材掉落概率 |
| `encounter_daily_supply` | 3 | 每日遭遇挑战补给 |
| `encounter_daily_recoveries` | 3 | 每日补给购买次数 |
| `encounter_recovery_cost` | 50 | 每次补给购买钻石成本，初值取原生常量 |
| `union_daily_attempts` | 3 | 每阵营每日挑战次数 |
| `disaster_free_summons_per_day` | 5 | 本地免费召唤额度 |
| `disaster_patrol_default_level` | 1 | 原生传入默认巡逻参数时采用的等级 |
| `battle_treasure_s_seconds` / `battle_treasure_a_seconds` | 120 / 180 | 宝箱 S/A 计时门槛 |
| `battle_treasure_b_drops` / `battle_treasure_a_drops` / `battle_treasure_s_drops` | 1 / 2 / 3 | 宝箱各档本地奖励数量 |

普通战场使用[主线战斗](main-story-battle.md)中的本地掉落概率与额外掉落规则。已经生成的战场及掉落不会在结算时重新抽取。角色及公共加成的生效时机见[养成、奖励与解锁](progression-and-rewards.md)。

## 范围与限制

各模式已有原生请求契约和隔离存档的流程检查，包括消耗、奖励、防重复及跨模式状态隔离。模拟战报通过不能代替原生画面、实际技能表现、地图操作、通知动画、难度和客户端重启续接的验收。

常驻外传已检查主脚本、分段脚本、显式资源引用，以及战斗的场景部件、敌人、Boss 模型和入口资源。动态计算的动画、技能、表情，以及关卡图片和音乐仍需通过实际播放确认。

会话恢复使用服务端保存的队伍、战场和进度，不恢复未上传的逐帧现场。回退到不支持当前进度结构的旧版服务端时，应同时恢复对应版本的存档备份。
