# 活动与本地复刻

已接入下列活动玩法，另支持奖励关和遭遇活动。默认开放主表中已有活动，参加条件和关卡前置继续生效。适配版本与主表内容数量见[更新记录](../changelog.md#内容快照)。

当前已核对缓存仍缺少部分活动背景预制体，范围见[内容快照](../changelog.md#内容快照)。主表中的 `SE_DUMMY` 音效引用仍需确认原生容错。不能把后端测试通过理解为活动页面或完整剧情已实机通过。

## 玩法范围

| 类型 | 已接入流程 |
| --- | --- |
| 采矿 | 矿车、成功／失败分支、C/B/A/S 评级、次数恢复、首通、重复奖励、扫荡 |
| 凶化厄灾 | 持续血量与阶段、出战角色限制、设施编队和燃料、重置、扫荡、个人榜与排名邮件 |
| 剧情活动 | 剧情前置、普通关与挑战关、首通／重复奖励、可扫荡关卡、回想防双领 |
| 寻宝棋盘 | 消耗活动币开格、中奖推进、重复请求防双领、最终棋盘循环 |
| 狩猎 | 体力关、首领券、首领关、活动效果升级与开关、后日谈解锁 |
| 箱池 | 限量奖池、抽取次数、累计／增量返回、重要物品重置条件、最终箱循环 |
| 委托 | 前置解锁、关卡奖励、最快时间、最高 FC 伤害任务、原生编队支援效果 |
| 养成 | 剧情、每日次数、关卡推进、免费固定队伍试玩 |
| 竞速 | 分组解锁、单关／整组最快时间、稀有度及纹章限制任务 |

奖励关支持出现、放弃、挑战、首通和扫荡。遭遇活动使用原生 `encount_type=10/11`；普通遭遇保留 `0`。只让当前选中的遭遇活动影响地图、间隔与每日容量，历史参与和已取得进度保留。

## 档期、参加条件与存档

任务分类、条件礼包、功能解锁奖励与旧档兼容见[养成、奖励与解锁](progression-and-rewards.md)。

`gameplay-rules.json` 默认 `event_open_all=1`，使主表已有活动可选；设为 `0` 后可通过 `event_open_ids` 指定重开活动，空列表则按原日期。重开同时覆盖活动入口、关卡与剧情日期、相关任务、兑换期限，以及关联卡池和代币期限。

原始主表 blob、素材清单和存档仍绑定原始版本。服务端生成独立 `events-...` 资源版本，同步活动档期及关联日期。已发布的派生主表和元数据缓存在 `master/event-views/`，按内容哈希校验；四份内存视图的淘汰和进程重启不会使已发布 URL 失效。配置变化会更新资源版本，客户端的实际刷新时序尚未实机验证。

普通活动横幅按活动 ID 跳转，支持多期同类活动。遭遇活动的原生界面固定选择日期有效的第一期，没有多期选择器，因此客户端主表按当前认证存档只开放所选的一档；首次使用默认首期。可在控制台使用“选择遭遇活动”切换，响应携带对应的新资源版本，不依靠参与历史数组排序。

开放日期不绕过主线门槛：普通活动要求完成 1 章 1 话，委托要求完成第 3 章，凶化厄灾要求完成第 6 章。关卡自身前置和试玩条件继续生效。

不同活动 ID 的进度、次数、奖池和战绩分开保存。同一 ID 重新开放不会自动清空已领奖记录，`epoch` 用于识别实例。已合法进入的战斗可在到期后结算，但仍检查活动归属、实例及重置版本；新的参加、开战、恢复和扫荡继续检查档期。

控制台提供“重置整个活动实例”和“重建指定活动箱池”。这类操作要求没有正在进行的战斗，并明确允许重新获取奖励。整活动重置会递增实例版本，清理该活动进度及任务、剧情、兑换记录；已经获得的货币、道具和邮件保留。重建箱池同样保留原有奖励，因此执行前应先备份存档。

## 奖励、任务与兑换

活动任务按真正的 `m_mission_terms.category_group` 归属处理，分别维护限时任务和限时日任务。任务编号前缀不作为活动归属依据。剧情任务使用原生战斗定义 ID，不能把剧情节点 ID 当作同一 ID。

回想和活动剧情共用首奖领取记录；已阅读不直接等于活动战斗前置完成。首通奖励、通关次数、普通重复奖励分别维护。扫荡累计通关次数，不伪造最快时间、最高 FC 或限制队伍战绩。重复读取旧任务请求会刷新当前数值和领取状态。

活动货币是 `content_type=54`，首领券是 `56`，全局时限资源是 `120`；抽卡代币 `170` 与活动币分开。活动币进入既有背包和兑换事务，箱池、棋盘与兑换使用同一余额。

普通体力关、主线周回和常驻外传能产出已参加活动的体力币，并触发匹配奖励关。基础币按原生公式 `ceil(体力 × boost_rate / 1000 / stamina_base)` 计算，没有匹配倍率则为零。结算与扫荡返回实际活动掉落。

角色掉落加成按出发／上次通关阵容冻结，并按奖励类型和 ID 匹配。狩猎首领关的升级效果由原生 `StageEffectModel` 能力链应用；服务端写入等级和开关，不重复把同一效果叠入角色数值。

## 明确的本地规则

无法从客户端恢复的服务器规则保留为本地实现：

- 采矿单场矿战默认 60 秒，`event_miner_battle_seconds` 可调整；补给默认 3 次。两种次数购买默认每日 3 次、每次 50 钻石，对应 `event_miner_recovery_*`、`event_mutant_recovery_*`。
- 凶化厄灾榜单仅显示当前真实本地玩家。`event_mutant_ranking_reward_on_query=1` 时，有有效挑战成绩后首次查询按个人榜名次发一次邮件；设为 `0` 关闭这项本地发奖策略。这不是官方多人榜或截止结算算法。
- 棋盘按模板洗牌，箱池按剩余数量抽取。奖励关使用主表基础概率、失败递增和成功重置；角色加成只叠在本次阈值上，不污染基础概率。`event_bonus_character_rate_scale=1000` 表示完整应用主表角色加成，`0` 表示关闭。
- 遭遇活动的额外每日容量、首次加入补足及当前活动选择属于本地规则。主表若出现混入普通地图的非零概率，或奖励关出现非零编队限制组，需要单独核对和适配。

旧凶化厄灾 1050001 缺少原始首领显示元数据。衍生视图补入保留 ID `99001050001`，名称取实际敌人，显示属性为原生允许的 `None=0`；真实敌人、阶段和战斗属性不变。该显示记录不会加入普通厄灾的出现列表。

## 资源与限制

当前已核对缓存缺少部分 Event BG 预制体，明细见[内容快照](../changelog.md#内容快照)。缺失文件会影响相应页面，其他环境应以各自导入的资源清单为准。

活动流程已有原生请求契约与隔离存档检查，资源检查覆盖已解析的战斗场景、敌人模型、矿车和剧情引用。原生操作、页面布局、剧情音效容错、真实战斗表现、档期切换及重启续接仍需按具体活动实际验证，不能由接口测试结果推定完整通过。

回退到不支持当前活动进度结构的旧版服务端时，应同时恢复对应版本的存档备份。
