# 养成、奖励与解锁

[文档目录](README.md) · [控制台操作](../console/README.md)

本篇说明 PC 1.15.0 的常驻行为与本地规则。主线流程见[主线战斗与教程](main-story-battle.md)，活动玩法见[活动与本地复刻](events-and-reruns.md)。

## 任务批量操作

控制台“任务与邮件”中提供三种独立操作，均先预览、再应用到当前选择的存档：

| 操作 | 效果 |
| --- | --- |
| 开放特殊任务天数 | 选择任务组后开放到指定天，或勾选“开放全部天数”；保留原来的七日分页，不改变任务条件或发奖 |
| 批量设置任务完成状态 | 按类别、分组或任务 ID 标记当前周期的任务完成；关闭“标记为可领取”可恢复正常条件判断 |
| 领取所选或本组全部可领任务奖励 | 按正常前置顺序发奖，全选时跳过未完成、未开放和已领取项；新手总奖励仍使用独立总奖励操作 |

新手七日任务选择任务组 `101`。可以先开放七天，再批量完成，最后按需要手动领取；每一步都可独立使用。恢复自然开放时，取消“开放全部天数”并把天数设为 `0`，已领取奖励和完成凭证保留。

完成与领取覆盖普通、每日、每周、成就、特殊七日、通行证、活动、遭遇活动、深渊、开发计划和有有效配置的访客任务。普通及深渊类别的分组填 `0`；其他类别通过选择器选择对应任务组、活动、通行证或计划。遭遇活动使用当前已参加的一期。

这些操作不改角色等级、主线战绩等实际培养状态。未取得的回归资格、未参加的活动、已到期的任务和缺少主表定义的访客任务仍会明确提示或跳过，不会伪造成功。签到和订阅的每日发奖独立于任务完成状态。

完成覆盖只属于当前周期：下一日、下一周、下一期通行证或重置后的活动不会自动完成。深渊循环任务的一次完成标记只对应一轮领取。重复请求和重登不清除领奖账本。

七日任务按首次打开任务组后经过的北京时间 **04:00** 计算天数，不要求连续登录或在线等待 24 小时。普通每日和活动日任务也按 04:00 切换，普通周任务按周一 04:00，通行证周任务按下文的开期星期。旧自然日统计保留原始记录与总数，无法按小时拆分的历史值沿用迁移时可见进度；新记录使用重置日统计，旧领奖凭证保守兼容，不重复发奖。

任务设置在刷新游戏页面后生效；服务端代码更新需要重启服务，并刷新控制台以加载新操作。开放天数只投影客户端收到的开始日期，存档中的真实起止时间保持不变，导出和恢复存档会保留这些设置。

## 功能解锁与资格

主线完成使用原生终态 `sequence=99`，必须完成该话的战斗和收尾剧情。旧档中已有通关领奖记录、但仍使用旧终态的关卡会修正状态，不重新发放首通奖励。

入口提示、功能解锁和新手引导是独立状态。显示“已解放”后，客户端仍可能在首次进入对应页面时提交解锁；服务端按同一条件校验深渊、势力任务、常驻外传和同步研究。已开始的战斗允许继续、结算或退出，不因入口条件后续变化而卡住。

### 工作人员与功能奖励

酒馆工作人员、派遣资格和“三名工作人员”的功能条件统一使用原生标准：角色羁绊等级至少为 1。初始角色没有例外。旧配置 `tavern_staff_intimacy_level` 继续接受，但不改变这一标准；达到羁绊等级要求并不等于完成其他剧情前置。

功能解锁奖励来自 `m_feature_lock_rewards`。当前配置为功能 1 的骨材（50004）×5、功能 6 的道具（140001）×12，按奖励记录 ID 领取一次。旧档已解锁但未记账的奖励会补发；研究教程曾发放的骨材会抵扣对应数量，先解锁再领取教程补给也使用同一抵扣规则。

账本保存在 `features.feature_unlock.data.reward_claims`，记录补发、抵扣及实际到账数量。控制台触发的解锁也走同一账本；关闭再开启功能、重新登录和重复请求不会重发。

### 活动任务与条件礼包

活动任务列表按任务分类 `category_group` 查询，不能把分类号当作活动 ID。前三期遭遇活动共用分类 10000，列表及领奖使用当前选择的已参加期；历史期的成绩和已领奖记录保留，禁止跨期领取。

遭遇战开始时冻结任务所属期，结算时不会因为切换活动而计入另一时期。旧档只将能够确定归属的通关次数迁入分期统计，不从全局击杀数猜测历史活动成绩。

条件礼包分别检查指定角色、所属活动、关卡、箱池、棋盘和任务。复刻投影同时更新关联礼包的销售日期，但不会延长已经触发的限时倒计时，也不清空购买次数。旧档中曾被错误条件开放的礼包会重新核验资格，已购买的物品不回收。

一次性推荐礼包购买后从主页和商店推荐列表隐藏。旧页面再次提交相同购买时返回空结果，不重复扣费、发奖或累计购买次数；普通限购、订阅和阶梯商品仍按各自规则处理。

以下两项是明确的本地规则：

- 棋盘礼包 260099、260100、260101、260102 的主表条件值均为 1，与商品描述不一致。`recommendation_board_sheet_requirements` 默认分别使用 2、4、6、8，可在玩法配置修改。
- 竞速剧情限制表尚无完整原生字段定义。当前通过绑定数据哈希固定解释唯一记录：活动 1100001 的关卡 1100001103 达到通关终态后开放剧情 100000101。陌生限制类型或不匹配的数据会报错，不直接放行。

### 回归福利

回归资格采用可配置的本地判定：`comeback_inactive_days` 默认 30，前一次记录的活跃日期与本次相隔至少 30 天才登记资格；首次建档不算回归。设为 0 可关闭自动登记。有效期取 `m_come_backs.limit_days`，并受主表结束日期限制；系统时间回退不会授予新资格。

回归礼包、特殊任务及未购买的回归登录福利均校验资格。资格到期后停止新的购买和领取，但已购买的登录礼包按自身期限继续发放。再次回归不重置既有购买次数或一次性任务领奖记录。

这些检查和迁移在下一次存档读取或操作时执行，不要求新建存档。服务端代码更新需要重启服务；派生主表变化后需要重新登录游戏，使客户端获取一致的日期与条件。

## 等级与收益加成

### 等级与角色能力

服务器保留角色的原始培养等级。研究 `11001` 解锁后，客户端玩家参数和新建深渊队伍使用同步等级；未解锁时仍使用培养等级。等级任务、研究前置条件和活动伤害详情采用同一有效等级。固定教程队伍不继承玩家的同步等级。

角色与装备的额外掉落能力按当前出战编队汇总，技能等级不重复乘以效果值，仓库角色不计入。普通战斗在开始时记录能力贡献，结算按该场已经生成的奖励清单发放。扫荡保留最近通关时的编队能力贡献，公共 VIP、订阅和设施加成在扫荡时计算。旧档没有该贡献记录时，首次使用现有编队回退，重新通关后保存正式记录。

### 收益发生时刻

自然主线进度、VIP、研究、编队和装备变化前，先结算已完成的旧收益周期；变化后再刷新探索等级、上限和派遣关系。增加上限只延长仍在进行的派遣，不自动复活已经停止的队伍。

降低探索队容量会结算并撤回超出的派遣，保留编队配置和未满一个周期的进度。重新扩容后可再次派遣。

控制台的时间相关操作在确认时重新计算，预览不提前授予权益。通过控制台发布规则或主数据时，每个兼容存档先按旧配置结算，再启用新配置。旧格式验证档保持原样并显示迁移提示。

### 深渊

新远征冻结队伍的有效等级、魔晶石研究等级、完整本地规则及深渊主表。旧远征首次访问时补建规则快照，不重建队伍。相关快照经过压缩并受大小限制。

规则热更新对后续新远征生效。仍有远征进行时不发布主数据，以免客户端重载了新公式、服务端却保留旧公式；结束远征后即可发布。

### 活动与扫荡

奖励关的固定活动币奖励应用特效角色倍率。活动普通战斗和扫荡共用随机掉落增强，采矿与凶化厄灾也统一记录出战角色。首通奖励不重复叠加活动币倍率。

原生扫荡界面自行加上公共掉落加成。下发的保存概率仅包含关卡和通关队伍部分，避免 VIP、订阅和设施重复计算。

### 外观羁绊点

外观 `bonus_bond_point` 按本地首次获得规则发放一次：

- 角色服装和专属武器外观发给对应角色。
- 通用武器外观发给武器类型匹配的各角色，每个角色各一次。
- 先有外观、后有角色时补发该角色的首次奖励。
- 零值也保留处理记录；后改主表、重复获得、换装、重新登录不会再次发放。
- 删除后重新获得角色不清除历史凭证，避免重复领取。

当前主表的外观附加羁绊点均为零。首次加载旧存档时按现有配置建立凭证；修改非零值前应通过控制台查看预览和备份。

## 主页角色礼物

普通礼物按本地规则每天北京时间 04:00（日本时间 05:00）刷新。到点后的首次主页请求生成新批次；关游戏、重新登录、领取礼物和好感变化都不重抽当前批次。

### 抽选与领取

- 每批默认 3 位，受 `home_greeting_limit` 控制；从已拥有且满足好感条件的角色中抽选，每位角色只占一个位置。
- 尚未完成的好感剧情优先，同一角色依好感门槛顺序出现；其余位置随机抽选普通礼物。
- 普通礼物位置随机选择；剧情配置了固定位置时优先保留，位置冲突时改用空闲位置。
- 名单、位置、截止时间和领取凭证一起保存。领取后不补位，重登仍返回 `is_received=1`，由原生客户端隐藏礼物。
- 好感剧情按 `t_novel_homes` 中的剧情 ID 只领取一次。新解锁剧情进入下一批候选，不覆盖当前已领普通礼物。
- 同一次请求重试沿用原回包；使用新请求重复领取返回空奖励，不再增加道具。发奖和凭证由同一个存档事务提交。

`home_greeting_reset_hour` 使用日本时间，取值 0–23，默认 5。控制台可以修改；当前批次不会因此提前刷新。把刷新时间调晚时会延长当前批次，避免同一天多发一批。访客的日期和收据也使用同一生效周期；访客开关仍默认关闭。

当前主表有 11 组完全重复的普通问候条目，抽选时按角色合并，避免这些角色获得双倍抽中概率。旧记录引用重复条目时保留原 ID。

### 旧存档

首次访问主页时自动建立批次，兼容旧日本自然日和新日界之间的领取凭证。已经领取的礼物保留已领标记，原有未领剧情尽量保持原入口。旧凭证和剧情完成记录保留，不追扣历史多领的奖励。

迁移不改变存档外层格式，只在 `features.home.data` 增加 `greeting_cycle`。不支持此字段的旧服务端不能读取迁移后的主页状态；回退代码时应恢复修改前的存档备份。

## 通行证任务与领奖

通行证任务领取后发放通行证点数；达到等级后，普通奖励和已购买的高级奖励分别领取。领取记录持久保存，重复请求不会再次发奖。满级后的循环奖励按未领取的点数区间结算。

累计任务只统计当前通行证开始至结束之间的行为。周任务按通行证开始日期的星期，在日本时间 05:00（北京时间 04:00）刷新；第一周从实际开期时刻开始，最后一周在通行证结束时截止。例如 202611 通行证在周六开期，因此每周六刷新，而非周一。

统计保存在 `features.missions.data.pass_statistics`，普通任务原有的日统计和总统计保持独立。任务自带的有效期限会进一步缩小统计窗口。深渊成功结算归还、撤退或败退时登记一次挑战结束；重复结算、已结算记录的读取和单纯放弃未结算流程不会增加次数。

旧存档只从完整落在新统计窗口内的日记录恢复计数。开期当天、刷新当天等不足整日的旧记录无法可靠拆分，不推测其时间归属；这些原始记录仍保留。历史深渊结束次数未记录时也不补猜。已有通行证等级、积分、奖励和购买权益不变。

旧的 ISO 周领奖记录在对应历史窗口中保守映射为已领取，避免升级或回退系统时间后重复发奖；后续新周使用独立记录。只有当有效通行证存在可领取任务、普通／高级等级奖励或循环奖励时，主页通行证红点才亮。

## 更新与验证边界

具体修改的生效方式以控制台预览为准。领取持久化、防重复、时间窗口、迁移与加成计算有定向检查；这些检查不能代替原生界面的全部显示、伤害和交互验收。旧档格式说明见[新档与旧档兼容](newgame-policy.md)。
